# Desktop shell

Rules for `desktop/src-tauri/`: the Rust half of the desktop shell (D34). The repository-wide rules in [../../AGENTS.md](../../AGENTS.md) and the directory rules in [../AGENTS.md](../AGENTS.md) apply here too; the window's interface is in [../frontend/AGENTS.md](../frontend/AGENTS.md).

- Rust names no protocol method, event or error code, and `desktop/src-tauri/Cargo.toml` carries no serialization, HTTP or WebSocket dependency.
- The shell has five commands: `host_send`, `host_stop`, `host_restart`, `app_quit`, `default_workspace`. `host_restart` runs the same start path, which hands back the previous child and terminates it, so only one process ever writes frames into the window. Which session to take back is the interface's decision, carried by `session.open` (D30). `default_workspace` names the directory a first session belongs to while no workspace exists yet — the system documents directory, with `ligule/default-workspace` created inside it — and it reads no protocol frame and starts no process.
- Close and exit are two separate questions, and the tray answers only the second one's fallback (`close_action`, `exit_asks`): with a tray, close hides the window and the Host and rounds stay; without one, close keeps the window and asks the interface first, because hiding somewhere unfindable is worse. `ExitRequested` asks the interface unless the person already confirmed, whatever the tray did. So every way out — tray 「退出」, Cmd+Q, the close button, the last window going away — reaches the same interface check before `app_quit`. `stop` closes stdin before killing, so locks release.
- The shell looks for the backend in this order: `LIGULE_DESKTOP_CLI`, the bundled `app/dist/cli.js`, then `dist/cli.js` walking up from the executable. It prefers the bundled node over `NODE` and `PATH`.
- The installer type is written per platform: `tauri.windows.conf.json` asks for NSIS, `tauri.linux.conf.json` for AppImage and the Debian package, `tauri.macos.conf.json` for the DMG, and the bundler merges that file into `tauri.conf.json` with arrays replaced whole. `bundle.targets` has only the two shapes 「all」 or one list, so one shared list naming all four would ask a Windows runner to build a Linux package. The `desktop` job in `ci.yml` runs the four rows of `RELEASE.md` as a matrix, each on a runner of its own architecture; on every one of those targets it builds the pinned search packages, runs the core checks and the packed-artifact install, then builds the installer, checks what it is about to ship and uploads the files as attachments. It installs none of the four installers. `bundle.icon` must name a square PNG for the AppImage: with an empty list the Linux bundle stops at 「couldn't find a square icon to use as AppImage icon」.
- The installer carries its own runtime (D34). `node desktop/fetch-runtime.mjs` vendors the pinned Node, the built `dist/` tree, production dependencies and installed transitive optional dependencies into `desktop/vendor/`. The Node archive is chosen by `<platform>-<arch>`, defaulting to the machine running the script, and `desktop/node-pin.json` holds one file name and one SHA-256 per target — four targets, matching the rows in `RELEASE.md`, which `test/runtime-version.test.js` compares. POSIX extraction takes `bin/node` and lays it down as `node/node` with the executable bit set, Windows takes `node.exe`, and both carry Node's own `LICENSE` beside the binary. `desktop/vendor/node/.vendored` names the target and version that were fetched, so a leftover from another target cannot pass as ready. This includes platform native packages when installed and omits unrelated root optional dependencies such as the terminal UI packages. Only the native directories of the target platform are carried: foreign `prebuilds/<platform>-<arch>` and libc dirs, plus gyp's `obj.target` intermediates, are left out and the copied tree is walked afterwards to prove none remain — the AppImage's linuxdeploy runs patchelf over every ELF in the AppDir, and a musl-linked koffi copy fails the whole bundle. That directory is never committed, and `bundle.resources` mounts them as `node/` and `app/`. A runtime tree built on one platform must not be shipped for another: the native bindings inside it are the host's own, which is why each target's installer is built on a runner of that platform.
