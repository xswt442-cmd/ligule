# ligule 使用手册

开发中的自建 agent harness：内核不提供任何工具，一切能力都是插件。命令行、终端界面与桌面壳读同一份内核，会话记录是唯一事实源。

English version: [guide.en.md](guide.en.md)。工程约定与分层规则在 [../AGENTS.md](../AGENTS.md)。

## 三十秒跑通一次真实任务

装好并配好后，进到一个项目目录里跑一轮：

```sh
cd <你的项目根>
ligule run "把 README 的第一段改短一点"
```

模型要改文件时会停下来问你：`y` 允许这一次，`n` 不允许。一轮跑完，这次会话的记录落在 `<项目根>/.ligule/sessions/`。

日常使用建议起终端界面或桌面壳，两者都能连续对话：

```sh
ligule tui      # 终端里的那一扇
ligule host     # 桌面壳起的就是这一个进程；界面与后端走标准输入输出两根管道
```

## 安装

需要 Node 24 以上。包还没有发到 npm，从仓库装：

```sh
npm install
npm run build     # 产出 dist/，命令行与测试跑的都是这一份
npm link          # 让 ligule 这个命令可用；不想全局装就用 node dist/cli.js
```

终端界面的那几件可选依赖随 `npm install` 一起装上；装不上时 `ligule tui` 报 `tui_dependency_missing` 并列出那一份清单。

`ligule search` 用的 ripgrep 不在包里，另外建一次：

```sh
npm run build-rg
```

没有建时，那一次调用报出探测失败的稳定码，不会静默换成别的搜法。

桌面壳要 Rust 与 Tauri，Windows 上还要 WebView2 运行时（Win11 自带）：

```sh
cd desktop
npm install
npm run dev       # 前端 Vite 在 5188，壳连它，改界面即时可见
npm run build     # NSIS 安装包，产物在 target/release/bundle/nsis/
```

安装包自带一份 Node 运行时与内核的运行时树，所以装到没有这份仓库、也没有 node 的机器上能跑。壳的说明在 [../desktop/README.md](../desktop/README.md)。

## 配置

命令行、终端界面与桌面壳读同一份配置，优先级从低到高有四层：

| 层 | 位置 | 说明 |
|---|---|---|
| 用户 | `~/.ligule/config.toml` | 这台机器上的默认 |
| 项目 | `<项目根>/.ligule/config.toml` | 进仓库，给协作者共享 |
| 项目本地 | `<项目根>/.ligule/config.local.toml` | 不进仓库 |
| 命令行 | `--config 键.路径=值` | 一段 TOML 赋值，可以重复 |

嵌套的表逐键合并，数组与标量整份替换。

用户层所在的那一份目录就是应用数据根：默认 `~/.ligule`，环境变量 `LIGULE_HOME` 写一个绝对路径能让它整体挪到别处，写相对路径当场拒掉（`data_root_invalid`）。模式、技能、提示词模板与扩展的自动装载目录，终端界面的键位改动与草稿，以及两端共用的那一份输入历史，都在这一份目录下面。会话记录与项目层文件按项目根走，`~/.agents/skills/` 按主目录走，这两处不跟着数据根挪。桌面第一次使用建的那一具默认工作区自己没有配置文件，所以模型那一条要写在用户层：只写在某项目的层里，那一具工作区里读不到它。

密钥不写进任何一层文件——配置文件里的每个键工具都读得到——只走环境变量。默认读 `LIGULE_API_KEY`，用 `model.apiKeyEnv` 改名字。

最小的一份能跑的配置，尖括号里的值都要换成你自己的：

```toml
[model]
api = "chat-completions"          # 或 "messages"
baseURL = "https://<你的端点>/v1"
model = "<模型名>"
apiKeyEnv = "<装着密钥的环境变量名>"

[limits]
contextTokens = 200000            # 不写这一格就不做上下文压缩
```

能写的格子：`mode`、`policy`、`loop`、`limits`、`exec.shell`、`instructions`、`prompt.static`、`mcp.servers.<名字>`、`extensions`、`host.sessionDirectory`。每一项在[配置那一格](#模型与配置那一格)里说它管什么。

模式清单、技能、提示词模板与扩展各有自己的目录，不写在配置里：

| 东西 | 位置 | 想看装载结果 |
|---|---|---|
| 模式 | 随包 `modes/`、`~/.ligule/modes/`、`<项目根>/.ligule/modes/`，同名一份整文件生效 | `ligule tools` |
| 技能 | 项目与用户各自的 `.ligule/skills/` 与 `.agents/skills/`，按这个先后 | `ligule skills` |
| 提示词模板 | `<项目根>/.ligule/prompts/` 与 `~/.ligule/prompts/`，递归找 | 终端里打 `/名字` 时展开 |
| 扩展 | `~/.ligule/extensions/*.js` 自动装；用户层与命令行写的路径也装；项目层与本地层写的报 `extension_source_ignored` 不装 | `ligule extensions` |
| 工作区登记 | 数据根下的 `workspaces.json`：建会话与接会话各写一条，界面那一栏只是它的一个读者 | `ligule workspaces` |

## 命令一览

```
ligule run <文字>                 一轮问答，审批问在终端上
ligule resume <会话 id> <文字>    接上那一份会话，沿用它当时生效的模式
ligule tui                        终端界面
ligule host                       一行一条帧的协议端点，桌面壳起的就是这一个进程
ligule sessions [--json] [--project <根>]   列出跑过的会话，不建内核
ligule policy <会话 id> [--json]  这一次会话里判定怎么走的：三档计数与命中的规则
ligule workspaces [--json]        列出登记过的工作区，不建内核
ligule tools                      列出这一次会装上哪些工具
ligule skills                     列出这个目录会加载哪些技能，以及被跳过的原因
ligule extensions                 列出会装载哪几个扩展文件，以及被挡掉的路径
ligule call <工具> [json-参数]     单独调一件工具，不经过模型
ligule --help                     列出命令与选项
```

选项：`--config 键.路径=值`（可重复）、`--mode <名字>`、`--project <根>`、`--json`。`--mode` 盖过配置里的 `mode`；两处都没写时用随包的 `minimal`。

## 项目与会话

工具能读写的位置由边界决定。默认就是这一次指的那一根：命令行在哪里跑（或 `--project` 指了哪一根），工具就在哪里读写。任何一层配置写的 `boundary` 都盖得过它。

会话记录在边界下的 `.ligule/sessions/`：

```
<会话 id>.jsonl              一条一行事件，第一行是这份记录的元信息
<会话 id>.sub-<序号>.jsonl    派生执行体自己的记录
<会话 id>.checkpoint.json     压缩摘要与它顶掉的那一段
result-*.json                超过注入上限的完整工具内容
summary-*.txt                超过注入上限的完整摘要
```

命令行与终端界面：

| 想做 | 怎么做 |
|---|---|
| 开一份新会话 | `ligule run`，或终端里的 `/new` |
| 列出这个项目根跑过的会话 | `ligule sessions`，或终端里的 `/sessions`（可以用键盘选） |
| 接回某一份 | `ligule resume <会话 id> "接着做"`，或 `/resume <id> [模式名]`；id 写开头几段就行 |
| 起名字 | `/name <文字>`：列表那一行读它，模型看不见 |
| 归档与取消归档 | `/archive` 与 `/unarchive`：只改列表默认画不画它，记录照旧，也接得回来 |
| 在记录里找一段文字 | `/find <文字>`：说出是哪一份会话的第几条，序号交给 `/show` |
| 看某一条的完整内容 | `/show <序号>`；派生支线用 `/sub <序号>` |

序号都是会话记录里那个稳定的事件号，不是画面行号。

桌面壳的左侧栏「会话」那一栏：建会话时指名过工作区的那些在上面按工作区分组，组名读那份登记里的显示名，那一行没写过名字时才用目录那一段，完整路径挂在这一行的提示上；没指名的与更早的记录在下面直接排列，界面按记录首行那两格决定谁在哪，不按「这条路径等不等于现在的默认目录」推。一组可以收起，收起时那一行说清里有几份。「加一个项目」那一格写上另一个项目的目录就加进来：这份清单只是这一扇窗口想看着的那几份，存在本机偏好里，退掉一条只改这一栏画什么；持久的那份登记在数据根的 `workspaces.json`，用 `ligule workspaces` 列出来，这一栏读的就是这一份。每组标题行上有两枚按钮：「设为默认」把这一具备成新建会话时落的那一具，已经成为默认的那一枚写着「默认」，按下去退掉默认。「刷新会话列表」重读，读的那几项目录里包含登记里默认那一具，所以在那里建的第一份会话不用先指名就列得出来；「只看这一份」把查找限定在当前会话并读进溢出在文件里的整段正文，「新建」在那份工作区起一份会话，来源就记成指名过。没有按「新建」而由界面自己退一档时：先退到眼前这一份会话所在的项目，再退到登记里的默认那一具；两格都没有时，桌面壳交出系统文档目录下的 `ligule/default-workspace`，把它登记成默认并在那里建第一份会话。浏览器里没有壳可问，才用宿主自己那一份项目环境。这几种退法来源都记成默认。归档过的会话排在后面并标出「已归档」；正在跑的标「这一份在跑」，刚跑完而人没看着的标「刚跑完一轮没看着」，切过去就消。

桌面上没有改名与归档的入口：那两样在终端里做，桌面读的是同一份记录。

窗口那一记叉收起的是这一扇窗口，不是整个应用：后端进程、跑着的那一轮、等人答的卡与排着的几句都留着。把它找回来与真的退出走任务栏上 ligule 那枚图标的两条菜单，「打开 ligule」与「退出 ligule」。退出之前界面先列出这次会打断哪几份会话，默认那一枚是「返回应用」，另一枚才是「中断任务并退出」；草稿与排着的句子留在本机，下一次打开还在。那一枚图标立不起来的桌面，那一记叉按原来的样子退出，不会把窗口收进找不回的位置。

一份会话同一时刻只由一具后端进程持有。第二次打开时报 `session_locked`。

## 输入与队列

| 想做 | 终端界面 | 桌面壳 |
|---|---|---|
| 发送 | Enter | Enter 或 Ctrl+Enter |
| 换行 | Shift+Enter 或 Ctrl+N | Shift+Enter |
| 引用这个项目里的文件 | 打 `@` 出候选，Enter 或 Tab 换成 `@路径` 放进草稿而不发送 | 同一形状 |
| 翻发过的那几句 | ↑ ↓（草稿有多行时先移动光标） | ↑ ↓ |
| 在输入历史里反查 | Ctrl+R | 没有这一条 |
| 把草稿交给外部编辑器 | Ctrl+G，用 `VISUAL`（若已设置）或 `EDITOR` | 没有这一条 |
| 整段粘贴 | 作为一个整体进草稿：里面的换行不发起一轮，那一段里若有 `y` 也不替人答复审批 | 同一形状 |
| 撤销与重做草稿 | Ctrl+Z、Ctrl+Y | 输入框自带的撤销与重做 |

跑着的那一轮里按 Enter 不会丢掉那一句：它排进队列，本轮结束后按先后发出。

- 草稿空着时按退格收回排着的最后一条。
- 你按下 Esc 打断这一轮时，排着的几条一起停下。
- `/queue` 说出现在走不走；`/queue continue` 才接着发；`/queue drop <序号>` 与 `/queue clear` 把那些句子收回草稿而不是丢掉。
- 没发出去的那一句与排着的几条存在 `~/.ligule/tui-input.jsonl`，按项目与每份会话分开留住，下次打开同一份会话时回到原处；排着的几条回来时是暂停的。这份文件不是事实源：读不懂的那一行跳过，会话照开。
- 重连之后排着的文本不会自动发出去：它交回草稿，由人再按一次 Enter。

两端共用的那一份输入历史跨会话存在 `~/.ligule/tui-history.jsonl`：终端界面与桌面壳发出去的句子都进同一份，最新的排在最前，最多 200 条，它不进会话记录。草稿与排着的几条仍然各端各留各的，按会话分开。

## 审批与规则

档位是整个运行一份的，不按工具名分。能写的有两种：`ask` 逐次问人，`auto` 把读、写、执行一起放开；写别的名字报 `policy_mode_unknown`。每一次调用的判定结果有三种：允许、不允许、问人。

`ask_user_question` 问的是这件事该怎么办，审批那一格问的是这一件能不能做，两者各走一条请求与一次答复：这一件不进档位判定、没有回答时限，只有交出答案或者打断这一轮才收尾。终端界面与桌面壳都能答，纯命令行的下一次调用没人替它答，因此那一路不装载这一件。

| 想做 | 终端界面 | 桌面壳 |
|---|---|---|
| 答复这一次询问 | `y` 允许、`n` 不允许；Esc 取消这一轮 | 允许与不允许那两枚按钮；Esc 取消这一轮 |
| 看实际改动 | 审批框里展开；Ctrl+O 打开或收起 | 同一形状，抬头那格还写出这是哪一个项目里的动作 |
| 答复模型的提问 | 在输入里写一句回答，或写那一条的编号；回车交出这一道，最后一道答完才整份交出 | 选中那一条或写一句自由回答，再按「交出答案」 |
| 临时改这一份会话的档位 | `/policy ask`、`/policy auto`、`/policy reset` | 顶栏那枚牌子，`reset` 退回配置默认 |
| 看这一次判定怎么走的 | `ligule policy <会话 id>` | 「工具与档位」那一栏说当前档位、它来自哪一层、连续与累计的拒绝次数 |
| 保存默认档位与规则表 | 配置文件里 `[policy]` | 设置的「审批规则」那一栏 |

规则表四个字段：

```toml
[policy]
mode = "ask"

[[policy.rules]]
tool = "read"
decision = "allow"

[[policy.rules]]
tool = "exec"
decision = "allow"
match = "git diff*"
reason = "只读的 diff"
```

- `tool` 是工具名，或者 `mcp:<服务器>/<工具>` 那一串能力名。
- `decision` 是 `allow` 或 `deny`。
- `match` 是给命令文本用的前缀，或含 `*` 的通配。
- 没有命令文本的调用（`read`、`find`、`search` 这一类）要整件放行就不写 `match`：写了 `match` 的规则对这些调用不算盖住，还是会问。
- 一条命令被读成几段时（管道那一类），`ask` 这一档要同一条规则盖住每一段才不问人，几条规则各盖住一段还是会问。
- 命中的规则里只要有 `deny` 就拒绝，写在它前面的 `allow` 压不掉它；这一条在 `ask` 与 `auto` 两种档位都生效。
- `allow` 规则只在 `ask` 这一档参与判定。想只放开只读那几件，就留在 `ask` 并给读、找、检索三件各写一条放行规则，不要写 `auto`。

顶栏与 `/policy` 改的都只是这一份会话，不写文件。设置的「审批规则」那一栏写的是使用者默认或项目本机覆盖那两份文件之一，落笔只换那一块的字节，注释与键的顺序留着；它列出现在生效的那一张表与它出自哪一层。设置的每一栏手里还攥着没写进配置的编辑（或正写着一笔、答复还没读回来）时，关闭、按 Esc、点弹层外面或换到别的一栏都会先问一句，默认是留下继续写；要走得明确按「放弃这些修改」那一条。

连续拒绝到阈值时档位自己回到逐次询问。哪一次调用被哪一条规则盖住，跑完用 `ligule policy <会话 id>` 读得回来。

## 模型与配置那一格

`model` 那一段管模型与端点：`api`（`chat-completions` 或 `messages`）、`baseURL`、`model`、`apiKeyEnv`。桌面壳的「模型与端点」那一栏可以在界面上改这四格：先选写进使用者默认还是本机覆盖那两层之一，先预览再保存；保存之后谁什么时候用上它、这一条由哪一层写着，由同一处说出来。命令行写着的那一条改文件盖不过它。

其余的格子：

| 键 | 管什么 |
|---|---|
| `mode` | 用哪份装配清单；`--mode` 盖过它 |
| `policy.mode` | 默认档位；`/policy` 与顶栏只改当前会话 |
| `policy.rules` | 规则表，见上一节 |
| `policy.thresholds` | 连续与累计的拒绝阈值，到数回到逐次询问；默认连续 3 条、累计 20 条 |
| `loop` | 迭代与模型调用上限 |
| `limits` | 各处的字节与条数上限，含 `contextTokens` |
| `exec.shell` | `auto`、`bash`、`powershell` |
| `instructions` | 项目指令文件的预算 |
| `prompt.static` | 系统提示的静态段：四层都没写时用随包那一份基础提示，哪一层写了就整份换掉它 |
| `mcp.servers.<名字>` | `command`、`args`、`env`、`cwd` |
| `extensions` | 扩展文件的路径数组 |
| `host.sessionDirectory` | 会话记录落在哪一个目录 |

生效时间分三种：档位与规则表改完当场作用于后续判定；模型端点与模式等在会话的轮次边界上换上，界面上「这一份会话现在用的是」与「等在它轮次边界上的是」各说一句；命令行 `--config` 写着的那一条，改文件盖不过它。

## 历史与分支

| 想做 | 终端界面 | 桌面壳 |
|---|---|---|
| 浏览完整历史 | Ctrl+O 打开；PageUp/PageDown 翻页、Home/End 跳到两端、Shift+↑/↓ 选择行、Ctrl+Y 复制选中、Esc 关闭 | 转录区自己滚，行内可展开 |
| 看某一条的原文 | `/show <序号>` | 点那一行 |
| 看派生支线 | `/sub <序号>` | 「派生支线」那一栏 |
| 手动压缩上下文 | `/compact`（要写出 `limits.contextTokens`） | 命令面板里「手动压缩上下文」 |
| 复制最后那条回答 | `/copy` | Ctrl+Shift+C |
| 复制回答里的代码段 | 选中后 Ctrl+Y | 每段围栏代码下面的「复制代码」 |
| 导出全文 | `/export <路径>` | 「导出全文」那一栏，开这台机器自己的保存对话框 |
| 从这里分支 | `/branch [序号]` | 命令面板里「把这一份会话分支一份新的」 |

不带序号的 `/branch` 复制到此刻记录落到哪儿为止；带一个序号就复制到那一轮正常完整结束那一条，那一条用 `/show <序号>` 读得到。原来那一份一个字不动。上一份里没配上的那次派发不会自己重跑：第一次打开新的那一份时它补成「结果未知」。分支不另开一份工作区，同一项目里的分支写的还是同一批文件。

导出读完整记录、补溢出在文件里的整段正文，排版与落盘都在宿主那一侧；每条派生支线在同一目录里另写一份。对话框返回路径不等于文件已经写成：那一栏说的是宿主交回来的那几条路径，某一条支线读不回来、或它算出来的那一个文件名已经有一份在那儿（这一种不盖它）时，逐条说出是哪一个码或哪一条路径。

打断正在跑的那一轮会带走命令的整棵子进程。宿主被硬杀或崩掉时不会——那一次调用的结果在恢复时被记成 `tool_outcome_unknown`，界面与模型看到的都是同一句「不知道做没做成」。

## 恢复与排错

| 看到 | 意思 | 怎么办 |
|---|---|---|
| `session_locked` | 这份会话已被另一具后端进程持有 | 关掉另一扇，或等它释放；锁的主进程被硬杀后最多十秒失效 |
| 断连横幅与「重连」 | 后端进程退了 | 按「重连」：会换一具进程，再用 `session.open` 接回这一份会话。没答复的那些请求按 `host_restarted` 收尾，还没答的询问与提问作废 |
| `tool_outcome_unknown` | 宿主被硬杀或崩掉时那一次调用留下的 | 当作「不知道做没做成」，先确认实际状态再重做 |
| `config_field_unknown` | 界面提交的格子不在宿主白名单里 | 换那一格的名字；界面上能改的只有四条模型字段 |
| `data_root_invalid` | `LIGULE_HOME` 写的是相对路径 | 写绝对路径；没写这一格时数据根是 `~/.ligule` |
| `workspace_registry_invalid` | 那份工作区登记读不懂，或默认选择指向一个没登记的身份 | 按报出来的那一格改那份文件；也可以删掉它，之后由建会话那一条路重新登记 |
| `workspace_registry_version` | 那份登记由更晚的版本写过 | 换回那一版的可执行文件，或删掉那份文件重新登记 |
| `input_history_invalid` | 两端共用的那份输入历史里有一行读不成一句 | 按报出来的行号改掉或删掉那一行；整份删掉也行，下一次发送重新写出来 |
| `input_history_locked` | 另一处正在写那份输入历史 | 过一会儿再发那一句；两端同时发送才碰上得了 |
| `cli_command_unknown` | 命令名打错 | 跑 `ligule --help` 列一遍 |
| `tui_terminal_required` | 在非交互终端里起了终端界面 | 改用 `ligule run` |
| `tui_dependency_missing` | 终端界面的可选依赖没装上 | `npm install ink react marked highlight.js string-width` |
| `extension_source_ignored` | 项目层或本地层配置写了扩展路径 | 把扩展放到 `~/.ligule/extensions/`，或写在用户层与命令行 |
| `ligule resume` 报模式文件被改过 | 那份会话当时生效的装配清单与现在读到的不是同一份 | 用 `--mode <名字>` 或 `/resume <id> <模式名>` 显式指定用哪一份 |
| 记录第一行的格式版本对不上 | 那份记录由更晚的版本写过 | 换回那一版的可执行文件，或开一份新会话 |

四条只读的检查不建内核，也不问模型：`ligule tools`、`ligule skills`、`ligule extensions`、`ligule workspaces`。一次判定怎么走的用 `ligule policy <会话 id>`。

桌面壳找不到后端入口时，`LIGULE_DESKTOP_CLI` 指后端入口、`NODE` 指 node 可执行文件；安装包自带的两份优先级在 [../desktop/README.md](../desktop/README.md) 里。

## 当前限制

| 还没有 | 现在怎么做 |
|---|---|
| 多个窗口看同一份会话 | 一份壳对应一具后端进程；要换窗口就用另一扇壳的托盘菜单「退出 ligule」把它收掉，再在新窗口里接回那一份会话。那一记叉只是收起窗口，后端进程与它攥着的记录锁都还在 |
| 桌面里改名与归档 | 在终端界面用 `/name`、`/archive`、`/unarchive`；桌面读的是同一份记录 |
| 把图片交给模型 | `read` 交的是文本，没有那样的工具；多模态端点也只能读文字 |
| `ligule init` 与一条自检命令 | 照这份手册的[配置](#配置)那一节抄一份最小配置；装载结果用 `ligule tools`、`skills`、`extensions` 三处看 |
| 界面偏好那一格的多窗口共享 | 两扇窗口共用一份 WebView2 用户数据目录时读的是同一份存储，整份重写以最后落笔为准 |
| `plan`、`goal` 与 codemode | 不提供 |
| 代码签名、自动更新、MSI 与多架构分发 | 不提供；安装包是未签名的 NSIS |
