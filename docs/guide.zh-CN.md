# ligule 使用手册

ligule 提供命令行、终端界面和桌面界面。三种入口使用同一套配置和会话记录。

## 安装和启动

命令行包需要 Node.js 24 或更新版本。安装 npm 上当前公开的版本：

```sh
npm install -g ligule
```

v0.0.2 尚未发布；仓库中的版本不代表 npm 或桌面安装包已经发布。桌面版请使用对应平台已经发布的安装包。Windows 桌面版需要 WebView2 运行时。

在项目目录中运行 `ligule run "查看项目结构并提出建议"`，可以执行一轮对话。日常使用可以运行 `ligule tui` 打开终端界面，或启动已安装的 ligule 桌面版。终端界面需要交互式终端；脚本和管道使用 `ligule run`。

使用 `ligule --help` 查看命令。`ligule sessions` 列出当前项目的会话，`ligule workspaces` 列出已登记的工作区，`ligule tools`、`ligule skills` 和 `ligule extensions` 查看已加载的能力。

## 工作区和数据

终端界面和命令行默认把启动时所在的目录作为工作区。桌面版首次启动时会在系统文档目录下创建并登记 `ligule/default-workspace`；之后新会话使用设置中选定的默认工作区。桌面左侧栏可以添加其他工作区并查看其中的会话。

每个新会话只属于一个工作区。终端界面启动时准备新会话；桌面版启动时恢复上次打开的会话，没有上次会话时准备一个新会话。会话记录默认保存在用户数据根的 `sessions/` 目录。

用户数据根默认为 `~/.ligule`。设置绝对路径环境变量 `LIGULE_HOME` 可以更换数据根；相对路径会报 `data_root_invalid`。用户配置在 `~/.ligule/config.toml`，项目共享配置在 `.ligule/config.toml`，项目本地配置在 `.ligule/config.local.toml`。会话记录、工作区登记、终端输入历史、桌面偏好和密钥引用也由用户数据根管理。桌面偏好、草稿和待发送队列保存在数据根的 `desktop.json`；WebView 的 `ligule.ui` 只作首屏缓存。终端界面与桌面界面的草稿和队列分别保存。

## 配置模型服务

桌面版打开「设置」中的「模型服务」即可新增服务、填写接口类型、服务地址和模型名称，再选择默认模型。终端界面和命令行读取同一份配置；需要手动设置时，在配置文件中填写：

```toml
[model]
api = "chat-completions"
baseURL = "https://api.example.com/v1"
model = "model-name"
apiKeyEnv = "LIGULE_API_KEY"
```

`api` 可设为 `chat-completions` 或 `messages`。把密钥放入 `apiKeyEnv` 指定的环境变量；未设置 `apiKeyEnv` 时使用 `LIGULE_API_KEY`。桌面模型服务页面也可以把密钥保存到操作系统 Keyring。非空环境变量优先；Linux 使用 Secret Service，服务不可用时会明确报错。

服务和模型的默认选择影响新会话。会话输入区的模型菜单可以为当前会话单独选择模型；终端界面使用 `/model` 查看服务，使用 `/model <服务> <模型>` 切换。切换会话模型不会改写全局默认；会话运行时选择会在本轮结束后生效。

## 会话和输入

终端界面使用 `/sessions` 浏览当前工作区的会话，使用 `/resume <编号> [模式名]` 恢复会话；编号可以使用唯一前缀。桌面版使用左侧栏切换会话；顶部会话菜单提供重命名、归档、取消归档、分支、导出、查看子任务、刷新记录和压缩上下文。

在输入框中键入 `@` 可以查找当前工作区中的文件。选择候选文件只会把路径放进草稿，不会发送消息。按 Enter 发送；长消息按 Shift+Enter 换行。运行中的会话收到的新消息会排队，按顺序发送。取消本轮也会暂停队列；可以查看队列、继续发送，或把排队消息收回草稿。重连后排队消息会回到草稿，不会自动发送。

桌面版按工作区和会话分别保存草稿与队列；关闭窗口后再次打开仍可恢复。终端界面按工作区和会话保存输入草稿与队列。两种界面共用已发送消息的输入历史。

## 审批和设置

默认审批方式为逐次询问。终端界面在审批提示中按 `y` 允许、按 `n` 拒绝；桌面版使用审批卡上的允许或拒绝按钮。展开审批卡可以查看将执行或修改的内容。

终端界面使用 `/policy ask` 改为逐次询问，使用 `/policy auto` 选择自动判定，使用 `/policy reset` 恢复配置默认值。自动档仍受拒绝规则、守卫、命令语法识别和目标地址检查约束；无法确认安全的命令会转为逐次询问。桌面版输入区旁的工具与审批菜单提供相同设置。当前会话的修改只影响当前会话；设置中的「审批规则」可以保存用户默认或项目本地规则。审批方式和规则在保存后立即用于后续判定。

桌面版「设置」分为常规、外观、模型服务、审批规则和快捷键。模型配置选择用户默认或项目本地层后保存；运行中的会话会在本轮结束后采用模型配置变更。高优先级配置仍覆盖较低层的设置。离开含有未保存内容的设置页面时，界面会先询问是否丢弃修改。

## 分支和导出

终端界面使用 `/branch` 从当前记录创建分支，或使用 `/branch <序号>` 从已完成的一轮创建分支。桌面版顶部会话菜单中的「分支会话」会复制当前记录；转录中每个已完成轮次也有分支入口。分支会创建新会话，原会话保持不变。

使用 `/export <路径>` 将终端界面当前会话及其子任务导出为 Markdown。桌面版在顶部会话菜单中选择「导出 Markdown」，再选择保存位置。导出会报告每个文件的写入结果；已有的子任务文件不会覆盖，主会话文件会写入所选路径。

终端界面按 Ctrl+O 打开完整历史，使用 `/show <序号>` 查看单条完整记录，使用 `/sub <序号>` 查看子任务记录。桌面版可在转录中展开记录，并通过会话菜单的「查看子任务」打开支线列表。

## 恢复和取消

运行中的本轮可在终端界面按 Esc 取消，在桌面版按停止按钮取消。界面分别显示已完成、已取消、失败或意外中断的轮次。

桌面版显示断连横幅时，按「重新连接」重启后端并恢复当前会话。没有得到答复的审批和问题会作废；待发送队列会回到草稿。终端界面退出后使用 `/resume <编号或唯一前缀>` 恢复会话。

`tool_outcome_unknown` 表示进程意外退出时，某个工具调用是否完成无法确定。先检查文件或外部状态，再决定是否重做。`session_locked` 表示另一进程仍持有会话；关闭该进程后再恢复。终端界面退出后，先运行 `ligule tui`，再输入 `/resume <编号或唯一前缀>`；也可以从命令行运行 `ligule resume <编号> "<要发送的消息>"`。`host_model_config_missing` 表示模型服务配置不完整；检查 `~/.ligule/config.toml` 中的模型字段，或在桌面版「模型服务」中填写配置。`provider_credential_missing` 表示密钥环境变量或系统凭据库中没有对应密钥。`credential_store_unavailable` 表示系统凭据库不可用；Linux 请检查 Secret Service。

## 语言、外观和快捷键

桌面版在「设置」的「常规」中选择跟随系统、简体中文或 English；「外观」提供墨青、羊皮纸、蓝天、石墨、森林和黄昏六套配色，也可以调整字号、侧栏宽度和面板位置。CLI 和终端界面可以用 `--lang zh`、`--lang zh-CN`、`--lang en` 或 `--lang auto` 选择语言；`zh-CN` 与 `zh` 都选择简体中文。

终端界面的常用按键：Enter 发送，Shift+Enter 或 Ctrl+N 换行，Esc 取消本轮，Ctrl+C 退出，Ctrl+O 浏览历史，Ctrl+R 搜索输入历史，Ctrl+G 在外部编辑器中编辑草稿，Ctrl+Z 和 Ctrl+Y 撤销或重做草稿。按 `/bind` 查看或修改快捷键。

桌面版的常用按键：Ctrl+K 打开命令面板，Ctrl+B 收起或展开左侧栏，Ctrl+Shift+C 复制最新回答，Enter 或 Ctrl+Enter 发送，Shift+Enter 换行，Esc 先关闭打开的面板，再取消运行中的本轮。可以在「设置」的「快捷键」中查看或修改绑定。

桌面版提供五类系统通知：等待回答、等待审批、本轮完成、本轮失败和连接中断。可以在「设置」的「通知」中总开关通知并分别启用各类提醒；点击通知会打开对应会话。通知权限与系统通知设置会影响提醒是否显示。通知栏会显示会话名称和状态，不包含提示词、工具命令或密钥。当前尚未完成各目标平台上的真实通知验收。

托盘可用时，点窗口关闭按钮会隐藏窗口，后台会话继续运行。托盘菜单中的「打开 ligule」会恢复窗口，「退出 ligule」会显示受影响的会话并询问是否中断任务后退出。托盘不可用时，关闭窗口会先显示退出确认。

## 常见问题

- `tui_terminal_required`：请在交互式终端运行 `ligule tui`；脚本中使用 `ligule run`。
- `tui_dependency_missing`：终端界面依赖未安装完整；检查 npm 安装是否包含可选依赖。
- `data_root_invalid`：`LIGULE_HOME` 必须是绝对路径；未设置时使用 `~/.ligule`。
- `provider_model_required` 或 `provider_base_url_required`：检查服务地址、接口类型和模型名称。
- `resume_mode_changed`：恢复会话时指定其原有模式，或在终端界面使用 `/resume <编号> <模式名>`。
- 命令不熟悉时运行 `ligule --help`；在终端界面输入 `/help` 查看界面命令和按键。
